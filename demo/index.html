    When not to use it

    Notes

    Feedback at the pointer works when it’s about the gesture and over when the gesture is. Reach for something else when:

    • The result outlives the gesture or needs action. Use a toast with Undo.
    • It’s a plain button click. Show the status on the button.
    • The text is long or needs more than one line.
    • It needs to be clicked. It moves away from the pointer.
    • It would be the only feedback on touch or keyboard. Reflect the outcome in the UI too.

    API

    <cursor-status></cursor-status>
<script type="module">
  import '@yuskraft/cursor-status/define';
  const status = document.querySelector('cursor-status');

  status.show('Removing 3 files', { kind: 'progress', progress: 0, dots: true });
  status.progress = 0.4;              // springs smoothly
  status.success('Removed 3 files');  // ring → check, lingers, fades
</script>

    Methods

    MethodDoes
    show(label, opts?)Show, or morph if visible. opts: kind, progress, dots, icon.

    Theming

    Custom properties on the element. It ships dark and light variants: the light one follows prefers-color-scheme, or force either with theme="light|dark". Style the internals with ::part(pill), ::part(icon) and ::part(label).

    Accessibility

    • It’s supplementary. The pill shows how a gesture is going; the real outcome must also show up in the UI (the row disappears, the file appears in the list).
    • Screen readers hear results, not ticks. The visual pill is aria-hidden; state changes and final results go to a polite live region inside the element.
    • Keyboard and touch. Every demo here also works from the keyboard. On touch, the pill sits above the finger. Use follow="manual" with moveTo() to anchor it to a focused control.
    • Reduced motion snaps position and keeps only the fade. Forced colours switch to system colours with a visible border.
    • Contrast of the text on both default surfaces is above 4.5:1, even over white or black.
